# Телефон, работа 24/7 и хранение данных

## Доступ с телефона в домашней Wi‑Fi сети

Dashboard слушает `0.0.0.0:8765`, а удалённые клиенты защищены Basic Auth.

1. Ноутбук и телефон должны быть подключены к одной Wi‑Fi сети.
2. На телефоне открыть `http://192.168.1.140:8765` (адрес ноутбука может измениться после переподключения).
3. Логин: `polybot`.
4. Пароль находится в локальном файле `данные/.dashboard_password`. Он создаётся автоматически и не попадает в Git.
5. Если Windows спросит разрешение для Python в Firewall, разрешить только частные сети.

Сейчас автоматическое создание правила получило `Access is denied`. Один раз открыть PowerShell **от имени администратора** и выполнить:

```powershell
New-NetFirewallRule -DisplayName "Polybot Dashboard 8765" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8765 -RemoteAddress LocalSubnet -InterfaceAlias "Беспроводная сеть" -Profile Public,Private
```

Правило ограничено локальной подсетью и Wi‑Fi-интерфейсом. После этого проверить адрес с телефона. Если IP изменился, выполнить `Get-NetIPAddress -AddressFamily IPv4` и взять адрес интерфейса `Беспроводная сеть`.

Не пробрасывать порт 8765 напрямую через роутер: Basic Auth без HTTPS не предназначен для открытого интернета. Для доступа вне дома использовать приватную VPN-сеть (например, Tailscale) или HTTPS reverse proxy на VPS.

## Ночь при включённом ноутбуке

- В Windows установить «Переход в спящий режим: Никогда» при питании от сети.
- Отключить гибернацию на время эксперимента и оставить ноутбук на зарядке с нормальным охлаждением.
- Создать три задачи в Планировщике заданий: collector, demo engine и dashboard. Триггер — «При запуске системы», действие — соответствующий `.py` через `.venv/Scripts/python.exe`, рабочая директория — корень проекта, опция — автоматический перезапуск при сбое.
- Не запускать вторую копию каждого процесса: перед автозапуском проверять CommandLine уже работающих Python-процессов.

## Работа при выключенном ноутбуке

Выключенный компьютер не может выполнять Python-код. Для настоящего 24/7 процессы и рабочая база должны жить на постоянно включённом узле:

1. Небольшой Linux VPS в близком регионе: сначала collector + paper engine + dashboard; LLM на CPU туда не переносить.
2. Создать отдельного системного пользователя, Python venv и четыре systemd unit: collector, paper engine, dashboard и ежедневное резервное копирование.
3. Dashboard публиковать только через Tailscale либо HTTPS reverse proxy с дополнительной авторизацией.
4. SQLite хранить на локальном SSD VPS, не в OneDrive/NFS. Делать ежедневный online backup через SQLite backup API и копировать зашифрованную резервную копию наружу.
5. Модели обучать на ноутбуке; на VPS доставлять только проверенный компактный артефакт CatBoost/custom. Это снижает RAM, задержку и стоимость.
6. Сначала перенести только сбор и demo на 7–14 дней и сравнить пропуски, задержку и идентичность расчётов. Реальный executor всё ещё должен оставаться заблокирован.

## Как не раздувать хранилище

Хранить бессрочно:

- независимый итог 5-минутного события и Price to Beat;
- компактный feature vector на выбранных временных срезах;
- исполненные решения, модель/версию/конфигурацию, комиссии и net PnL;
- action-value и counterfactual примеры, прошедшие проверку качества;
- артефакты моделей, отчёты walk-forward и lineage датасета.

Хранить ограниченно:

- сырые сообщения — отключены;
- каждый тик цены/стакана — 90 дней;
- WAIT/HOLD решения — выборочно, 30 дней;
- частые equity snapshots — 30 дней;
- техническую телеметрию — 90 дней.

Retention теперь удаляет старые `external_prices`, `market_snapshots` и `reference_price_snapshots`, но сохраняет размеченные признаки и торговые результаты. Для долгой истории лучше ежесуточно складывать завершённые события в Parquet, разбитый по `year/month/day`, а в SQLite держать live-окно и индексы. Parquet нужен для обучения/аналитики, SQLite — для текущего состояния и панели.

## Постоянное итеративное дообучение

Безопасная схема — не переобучать активную модель после каждого события:

1. Накапливать пакет, например 100 новых независимых событий.
2. Строить dataset snapshot с идентификатором, временем и hash списка событий.
3. Обучать challenger на прошлом временном окне.
4. Проверять только на более позднем, не виденном временном holdout/walk-forward наборе.
5. Сравнивать с champion по net PnL после комиссий, PnL CI, profit factor, max drawdown, Brier и калибровке.
6. Не заменять champion автоматически, если нижняя граница CI не выше нуля или ухудшилась просадка.
7. Новый артефакт сначала запускать в shadow/paper; переключение в панели разрешать только без открытой позиции.

Это защищает от утечки будущего, переобучения на собственных ошибочных действиях и случайной деградации активной стратегии.
